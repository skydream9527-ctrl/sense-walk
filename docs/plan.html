Product & Engineering Plan · v0.3

慢行SenseWalk

不是按时长结束的白噪音。你要在手机里控角色走，或到户外真的走—— 走满关卡距离才能通关。 路上感官由静默慢慢长出脚步、环境音与振动。不可跳过，不可加速，不可提前通关。

Week 1 已完成 进度 = 距离 虚走 · 实走 Android · Kotlin · Compose 文档 v0.3

1. 产品愿景

用「走完一段真实距离」锁住通关，强迫放慢节奏，仔细感受感官层的渐渐回来。

相对 v0.2 的关键跃迁：会话不再是「计时沉浸、长按就算结束」。 时间只铺感官；通关条件只有有效距离。放弃可以，但不算通关。
距离即通关未达要求距离，不能完成关卡。
不可跳过 / 加速无快进、跳关、倍速；虚走也有速度帽。
静是默认感官沿路程淡入，禁止突然满音量。
诚实且温柔防刷有上限；文案不羞辱。
少即是多场景 + 模式 + 开始。
无打扰无广告、不催分享。

2. 双模式行走

开局二选一；会话中途不可换模式，避免刷进度。殊途同归：都要走满米数。

手机控角色

Virtual Walk

屏幕上极简角色沿路径前进。按住才走，松手即停。

  • 速度硬顶（如 ≤ 1.4 m/s ≈ 5 km/h）
  • 无冲刺、无加速条、无看广告加速
  • 适合室内、夜间、先熟悉节奏

户外实走

Real Walk

人在真实空间走动，传感器累计距离 / 步数；屏幕更「空」。

  • 主路径：计步传感器 × 步长
  • 可选 GPS 辅助（户外）
  • 车载 / 过快 → 暂停累计

实走 Android 传感选型

方案APIMVP
步数计 TYPE_STEP_COUNTER / STEP_DETECTOR · ACTIVITY_RECOGNITION 主路径：步数 × 步长（默认 0.7m）
活动识别 Activity Recognition / Transition API 辅助：车载时暂停累计
GPS 轨迹 Fused Location Provider 可选增强；跳点用速度帽过滤
Health Connect 系统健康步数 / 距离 后续，非 MVP 必需

3. 关卡与距离门禁

这是产品的硬核规则——用来逼你冷静地把路走完，才能听见后面的层。

通关 ⟺ 本局有效距离 ≥ requiredDistanceMeters
不可跳过没有跳关、看广告跳过、拖动进度。
不可加速虚走有速度帽；实走过快不计或封顶。
不可提前通关未满距时结束键 = 放弃，不发通关。
时间≠进度用时只展示；完成态只认距离。

放弃 vs 通关

行为结果
放弃长按退出未完成；文案：「这段路还没走完，下次再续。」
通关走满要求距离「你走完了约 X 米 · 用了 Y 分钟」

关卡距离草案

场景要求距离约合步数
森林漫步400 m~570（步长 0.7m）
沙漠独行600 m~860
夜径350 m~500

进 JSON：requiredDistanceMeters；感官触发权威字段改为 atMeters（迁移期可双读旧 atSec）。

5. 诚实原则（轻防刷）

防的是「摇一摇秒通关」，不是审判用户。不做服务器反作弊、不做羞辱文案。

策略做法
速度帽虚走 / 实走均限制最大折合速度；GPS 跳点丢弃
车载检测in_vehicle 或过快 → 暂停累计，轻提示「好像不是在走」
无计步器引导虚走，或仅 GPS 并说明误差
文案「还需要再走约 N 米」——不用「作弊 / 惩罚」
隐私最小权限；位置可选；数据默认本地

10. 风险与对策

风险对策
觉得太难走完首关 350–400m；剩余米数可见；放弃不羞辱
刷步 / 摇手机速度帽；活动识别暂停；无社交奖励动机
GPS 漂移步数为主；跳点丢弃
不想出门虚走模式
旧「随时结束」预期引导：结束=放弃，走完才通关

11. 成功标准（MVP）

  1. 冷启动到开始行走 ≤ 4 次点击（含选模式）。
  2. 未达要求距离无法进入通关态；长按仅放弃。
  3. 虚走有速度上限，无加速控件。
  4. 实走可用步数完成至少一关。
  5. 森林关随距离推进感官层（无素材时 stub / UI 层提示亦可验收门禁）。
  6. 通关文案含距离；放弃文案温和。
  7. 主路径无崩溃。
