# Agent能力评估与据此分工（2026-10-21）

这是依据本项目最近实际交付的阶段评估，不是模型品牌排名、人格判断或通用能力认证。评价对象是可检查的源码、测试、素材、handoff和审核质量；硬件条件未覆盖的能力记“未验证”，不因为没有真机就判能力不足。代码基线2e6f266aaf8f0e3aed3e47b4388cc84bf82ff68d，PR35观察9bcfbaba356269ed43b6944d44c7fc1c531788d4。本轮曾用三个内部只读复核分工交叉检查这些证据；这不替代产品任务的正式独立审核。

## 结论先行

| Agent | 本项目观察到的水平 | 最合适的角色 | 不能直接外推的能力 |
| --- | --- | --- | --- |
| ZCode | 核心工程实现较强，具备主程所需的并发排错和回归意识；UI证据审读仍需复核 | 主程、复杂状态/缓存/恢复、生产接线、确诊缺陷修复 | 没有数据就不能认定已具备真机调优、耗电优化或最终审美验收能力 |
| MiniMax Code | 工具/素材加工执行较好；自主视觉判定和最终交接一致性中等、需明确标准 | 素材工程、确定性处理、编码预算、批处理脚本 | 不宜独立决定产品规则、最终视觉合格、Android核心逻辑或发布放行 |
| Antigravity | 协作组织和结构检查较强，追查/纠错有产出；报告事实准确性与运行验收目前不稳定 | 流程协调、原始证据采集、确定性检查、缺陷分级、顺序集成 | 不能仅凭其报告、测试数量或截图文件名作为唯一发布/视觉放行依据 |

没有使用“9分/10分”等精确分数，因为任务类型、样本量与设备条件不同。以下强项和限制可被具体文件验证。

## ZCode：继续做主程，但交付拆小、证据单独核

- SW019的LayerImageCache/SceneCatalogCache真正处理single-flight、取消/重试、字节预算与LRU，不只是换一个异步API。源码和对应测试可检查。
- 本轮新增11项LayerImageCacheTest与6项SceneCatalogCacheTest；全套329通过中，**新增是17项**，不把329全算成其本轮新写测试。竞态回归包含3万轮调度检查。
- SW019报告明确模拟器帧数据不可分辨，不冒称提帧；没有无测量池化，也没有拿注入步数当真机，这是良好工程边界。
- SW018早期报告将没有提示文字的H2截图算成已显示，说明运行证据审读曾过度扩张；日志/XML命中不能替代最终画面。原accepted保留，缺证仍Pending。

分工：SW020按“安全区布局→步长设置/服务/旧快照兼容→每局一次触感”三段提交/验收，同一任务整体完成后才accepted；随后SW025构建身份。候选获批后做SW023生产接线。安装阻断由其复现和最小修。不得自行终审自己的UI截图、真机表现或性能收益。

## MiniMax：给固定输入和可核对输出，先一层再扩批

- SW002的程序化光效修复后来获批入包，证明明确规范下可以完成素材加工；SW014/015以及R2 guard能按反例改工具，当前独立自检14/14、manifest122/122，存在真实工具工作量。
- 薄雾110m近黑、875m空地对称亮斑仍在报告中被统计“通过”；406320B按409600B宽限通过却不满足当前400000B要求，说明脚本成功不能代替审美/合同完成。
- manifest五层实际hash/bytes匹配，但handoff仍绑定511adf5且摘要保留处理前大小，说明最终元数据生成链没有同步，不是全部素材hash都坏。

分工：优先SW022，按批准SW021先交一层及真实接缝/offset预览校准，再完成另外两层。该校准属于SW022同一任务，不额外造“已批准资产任务”；未获正式批准仍是candidate。处理脚本统一生成导出、manifest和handoff摘要，减少手抄。QA实际看图，ZCode作为非候选作者补一份只读接线/视觉反馈，再由QA记录正式结论。

雨林SW006另分支做R3，只用封存原图，先修最终head/摘要和严格字节预算，再改mist/glade并重验。8/8与累计22不重置，不新增API；R3 manifest必须revision3。不要继续堆自定义预检数量来代替真实图像检查。

## Antigravity：保留独立QA职责，收紧证据范围与可运行性

- SW024性能比较协议、问题队列、像素/源码追加修正有价值，保留历史与设备Pending也合理；它能追查并纠正早期错误。
- 但近期出现多次事实失准：SW018把无文案截图说成提示已显示；SW021交付SHA抄错；SW006声称缺manifest/四项旧artifact哈希及引用不存在guard路径。SW019 review还描述了源码不存在的scenes/index.json、脉冲圆/旅人徽章及若干状态字段。正式结论必须绑定实物，不靠叙述流畅程度。
- SW024 Python检查主要是源码字符串、配置和已保存审计JSON断言，不是操作App的UI测试。androidTest中的SenseWalkRegressionInstrumentationTest是object/runAll(context)领域检查集合，未接通可发现的@Test/Runner调用入口；verifyTapToRevealMetersContract令displayedInt=m1.toInt后比较同式，并没有测试点击、显隐或真实屏幕。因此“已有7项UI回归”只能称草案/领域检查，设备UI覆盖仍未建立。

分工：领取[SW026](../../tasks/SW-026.md)，继续精确head/hash/预算/依赖检查、采集画面/录像/实际命令输出、分级反馈与集成；先追加上述事实修正。下一步把少量关键用例接成**可发现、能执行、会因真实UI错误失败**的测试；业务Gradle/依赖由ZCode按handoff处理，QA不越权。不要再增加只匹配实现字符串或自等比较的“通过项”。

关键视觉与发布结论增加非作者第二方复核：素材让ZCode只读核接线/画面；代码的UI/发布证据由QA采集后交协调方复核原始内容，实际体验由用户安装反馈补齐。没有第二方设备结果就准确写验证范围，不制造人工审批流程或宣称最终MVP完成。作者不能批准自己的产品，原协议所有权与保护规则不变。

## Trae：设计可复用，接线时按真实规则校对

SW021的34项文件哈希匹配，可编辑Python/SVG、拼接/阶段/跨屏参考及“设计模拟”标识完整，适合作为设计供给。本轮不新派Trae任务，不因校对问题重画全部设计或篡改批准spec。

已发现的可定位问题：ui_mocks源将夜径写800m，而正式night_path.json为700m；390×844表混用949.5px周期与1170px视口却写covers=true；设计说明将新增App绘制误指SW022。ZCode接线时以DEVELOPMENT/实际配置为准、统一dp/px重算；MiniMax仍只做候选，App代码归SW023。QA先交简短校对表，不照抄模拟图数字到生产。
