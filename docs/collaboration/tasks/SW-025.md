# SW-025 · 可追溯测试构建身份

owner=zcode，kind=code；初始queued，依赖SW020 accepted。沿SW018已交的签名/版本提案，只实现构建身份部分，不照抄尚未验证的伪代码，不生成或轮换任何签名密钥，不改包名/权限，不引入账户。

GitHub Actions注入可核实的构建号及源码短SHA，versionCode采用合法正整数、后续测试构建单调递增；versionName有明确阶段名和build/SHA。具体Gradle属性/env默认值、范围校验、非CI本地fallback与旧versionCode=1的升级关系写清；不能用不同workflow各自计数冒称全局单调。当前Android同一workflow的run_number可用，但实际发布序列仍需校验。

设置/关于等现成入口可查看versionName、versionCode、源码SHA，不依赖用户翻下载文件名；不要求等待SW023的新关于页。打包产物的真实version字段、可见内容、Release tag/源码SHA一一对应；不把合入后的文档commit写成冻结APK源码。

测试：属性缺失/非法值的可解释行为、现有云端test/lint/build通过、实际产出APK元数据核对。至少两次构建验证身份不同且versionCode递增；不因此自动发布两份同源码Release。无法执行的元数据/UI项Pending并交QA实核，不写伪造证书。

已知debug随机签名问题仍存在：versionCode递增**不能**解决证书冲突，不能承诺覆盖安装保留数据。固定测试签名留在单独部署配置提案，按PROTOCOL授权边界处理，不把私钥存仓库/日志或用反射绕过验证。本任务不影响用户继续安装现有build176。
