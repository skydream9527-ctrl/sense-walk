## 最终行为

- **F-001 修复前**：基线(0,1000) 后同刻 (100,1000)/(200,1000) 各 +0.7m——可无限同刻刷距。**修复后**：零/负有效间隔恒 0 米（1.4×0=0）；同刻高读数只推进计数基线（同刻合并），合并步数由下一个正间隔事件统一计距并封顶（连续 100 批同刻 → 全 0，其后单个事件封顶 1.4×间隔）；乱序时间回退事件整体忽略（步数由计数差自然带回，不重复累计）；步长 NaN/Infinity 被拒绝保持原值。
- **F-002 修复前**：进程死亡后 START_STICKY null Intent 重启 → 进前台但无会话（空通知）。**修复后**（模拟器实测 `am crash`）：崩溃 → 粘性重启 → 无 ServiceRecord、无「实走中」通知、进程空转存活——干净退出，不假装可恢复（快照属 T07）。
- **F-003 修复前**：硬件存在被当注册成功；注册失败无回退。**修复后**：注册结果取 `registerListener` 真实布尔值；counter 注册失败 → 错误页「计步传感器注册失败…可重试或改用虚走」+ 释放音频 + 干净退出；部分注册（detector 成功 counter 失败）被清理；重复 stop 幂等；detector 失败不阻塞 counter-only 实走。
- **F-004**：装配（IO 读配置）期间重复 start 一律 NONE（单飞，不建第二套控制器/音频/监听器）；装配完成时若已停止/终态 → 丢弃并释放临时资源。模拟器行为证据：HOME 往返后同一引擎连续累计（14m→25m，无重置无双计）。
- **F-005**：服务事件时钟由 `System.nanoTime` 改为 `SystemClock.elapsedRealtime`（与 `SensorEvent.timestamp` 的 elapsedRealtimeNanos 同基准——深度睡眠后两轴不再漂移；设备重启双方归零走「读数下降重建基线」）。health 类型依据记录在 `startAsForeground` 处注释（计步锻炼会话 = health + ACTIVITY_RECOGNITION；会话内音频非独立媒体职责，不机械追加 mediaPlayback）。CI 新增 **Release manifest guard**：`processReleaseMainManifest` 后断言 `DebugStepReceiver` 不在 release 合并清单。
