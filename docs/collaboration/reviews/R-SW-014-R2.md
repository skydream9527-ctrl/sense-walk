## 具体缺陷清单

### 1. R2-01（P1）：生产入口允许 manifest 测试标记绕过门禁
- **现象**：`preflight.py` 与 `dry_run.py` 默认入口允许在被测 `manifest.json` 中定义 `_fixture_mode=true` 与 `_expected_registry_status=queued`，从而绕过任务必须为 `accepted` 的生产门禁；
- **影响**：输入文件能够自主决定是否跳过安全检查，破坏了门禁的客观隔离性；
- **应有行为**：生产预检入口对一切输入一视同仁严格检查；测试模式必须由独立的 CLI 参数（如 `--fixture-mode`）或独立测试驱动注入，不能由待测 manifest 决定。

### 2. R2-02（P1）：透明度像素反向判定
- **现象**：`real_decode_image` 中将 `alpha > 0` 判定为透明像素：
  ```python
  alpha_frac = sum(1 for a in alpha if a > 0) / len(alpha)
  ```
- **影响**：对于一张完全不透明的图片（全像素 alpha = 255），此算法得出 `alpha_frac = 1.0`，并报告为“100% 透明”，导致透明通道校验完全失效；
- **应有行为**：应准确统计透明/半透明像素（如 `alpha < 255` 占比或有效透光区域分布）。

### 3. R2-03（P2）：检查图清单完整性缺失
- **现象**：`checks` 校验只循环已有声明，当 `manifest["layers"][i]["checks"] = []` 时预检直接通过；
- **应有行为**：必须强制校验必需的检查图集合（黑底、白底、洋红底、透明棋盘格及 alpha mask）。

### 4. R2-04（P2）：API 账本字段仅校验键存在
- **现象**：仅检查 `api_attempts_total` 等字段是否存在，输入负数（如 `-1`）依然通过；
- **应有行为**：必须校验尝试次数为非负整数，并实现跨 revision 历史累计验证，防止轮次重置尝试次数。

### 5. R2-05（P2）：严格批准链验证不完整
- **现象**：`dry_run.py` 去除 fixture 标记后，面对伪造的引用依然未能结合 registry 的已批准 review SHA 和 spec SHA 完整核实。

### 6. 隔离测试 fixture 质量问题
- `negative_real_oversize` 样本的目标文件仅 4414 字节，全景仅约 96KB，远未达到单图 400KB 或全景 2MB 的实际预算上限；其失败实际由 alpha 错误引发，未真实覆盖超预算拒绝逻辑。
