## 1. 字段模型与契约冻结决策

ZCode 在 `domain/session/SessionSnapshot.kt` 中实现的快照模型与契约草案 [contracts/session-snapshot.md](../contracts/session-snapshot.md) 完全一致。经 Antigravity 审查确认，模型字段可正式冻结为契约 v1：

| 字段 | 类型 | 语义约束与验证结论 |
| --- | --- | --- |
| `snapshotVersion` | `Int` (常量 1) | 快照结构版本，与场景 `schemaVersion`（当前为 2）严格正交解耦 |
| `sessionId` | `String` (UUID) | 会话唯一标识，恢复后沿用原 sessionId，不产生孤儿会话 |
| `mode` | `String` | `"virtual"` 或 `"real"`，与导航枚举保持一致；未知模式直接判为 Corrupted |
| `sceneId` / `sceneSchemaVersion` | `String` / `Int` | 校验场景有效性与 schemaVersion 是否一致；不一致安全回退为 Incompatible |
| `state` | `String` | 仅 `WALKING` 或 `PAUSED` 允许恢复；`COMPLETED` / `ABANDONED` / `IDLE` 等终态被坚决拒绝 |
| `savedAtWallMs` | `Long` | 系统墙上时间戳，严格仅用于 30 分钟时限校验（超过判为 Expired） |
| `bootCount` | `Int` | `Settings.Global.BOOT_COUNT`；跨重启标定为 `acrossBoot = true`，但不直接判定快照失效 |
| `meters` / `sPos` / `sBest` | `Float` | 关键进度；Validator 严格拒绝 NaN、Inf、负数、`meters > requiredMeters` 以及 `sBest < sPos` |
| `firedPhaseIds` | `List<String>` | 已触发相位集合；恢复后静默跳过，严防一次性相位提示二次重播 |
| `elapsedActiveMs` | `Long` | 累计活跃时长，非负，用于结果页与统计指标对齐 |
| `lastCounterReading` / `lastCounterEventMs` | `Long?` | 实走计步传感器诊断信息；恢复时不作为补距依据，强制重新校准基线 |

**序列化决策**：采用强鲁棒性的手动 JSON 解析（由于工程当前未开启 Kotlin Serialization 编译插件），具备前向兼容未知字段能力，任何损坏输入安全返回 `null`。

## 2. 独立 QA 验证套件执行结论

Antigravity 编写了独立的单元测试套件 [test_pr9_r1_verification.py](../../../tools/qa/test_pr9_r1_verification.py)，涵盖了契约草案中的全部反例与边界条件。12 项独立测试全部通过：

1. `test_json_roundtrip_and_forward_compatibility`：验证 JSON 序列化能够安全忽略未来扩展字段，保留原有数据。
2. `test_malformed_json_returns_none`：格式损坏的 JSON 输入直接返回 `None`，不抛异常崩溃。
3. `test_valid_snapshot_within_window`：30 分钟窗口内的正常快照评估通过。
4. `test_across_boot_remains_valid`：跨 Boot 场景准确标记 `acrossBoot=True`，允许继续恢复。
5. `test_expired_snapshot_rejected`：超过 30 分钟（如 31 分钟）准确归类为 `Expired` 并被丢弃。
6. `test_terminal_states_rejected`：`COMPLETED`、`ABANDONED` 等终态快照归类为 `Incompatible`，拒绝恢复。
7. `test_paused_state_accepted`：暂停态快照被正确识别为有效可恢复态。
8. `test_corrupted_numerical_values`：针对 NaN、Inf、负米数、超终点米数进行输入攻击，全部准确识别为 `Corrupted`。
9. `test_sbest_less_than_spos_rejected`：针对 `sBest < sPos` 的非法回退状态准确拦截。
10. `test_unknown_phase_ids_rejected`：含场景定义外未知相位的快照被拦截。
11. `test_scene_schema_version_mismatch`：场景版本变动时被识别为 `Incompatible`。
12. `test_active_session_competition_logic`：前台服务存活时优先重绑定活服务，不拉起二次恢复引擎。

## 3. 生产代码生命周期与架构审计

1. **快照保存触发机制**：
   - 每 5 秒定时器心跳保存；
   - 越过相位边界立即持久化；
   - 状态转换（暂停、继续、应用退至后台）即时触发写入；
   - 摆脱对系统不可靠的 `onDestroy` 回调的依赖。
2. **主动放弃与通关清理**：
   - 用户主动通关、放弃，或通过通知栏 Action 点击停止时，调用 `clearSnapshot()` 彻底擦除快照，防止死灰复燃。
3. **实走计步防作弊与缺口补算防护**：
   - 恢复实走时，`RealWalkEngine` 初始置位 `rebasePending = true`；
   - 首次接收硬件 Counter 读数仅用于重新标定基线，绝不因系统重启或杀进程导致中断期间步数被突发补算。
4. **感官系统静态重构**：
   - `SensoryCoordinator` 接收恢复米数，仅静态拉起当前米数对应的环境音 Loop（平滑淡入至目标增益）；
   - 一次性音效提示与历史脚步声绝不重播；音频焦点恢复机制严格生效。
