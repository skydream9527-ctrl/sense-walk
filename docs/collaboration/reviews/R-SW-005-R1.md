## 1. 独立审查总评

ZCode 在 SW-005 R1 中完成了核心算法领域模型的设计与实现：
- 引入了 `TerrainMotor` 状态机（`FREE`、`APPROACH`、`STABILIZE`、`HOP`），在接近坎（gap 前 3m）且输入紧张时进入减速与站稳状态（1.2s），并在站稳期间绝对冻结位移推进，避免了刷距缺陷；
- 增加了 22 项针对性单测，全量 296 项 JVM 单测本地及云端 CI（PR #14 run 38744519423）均通过；
- 提出了快照兼容性方案（不新增持久字段，版本维持 1，步态为内存瞬态）。

然而，经独立审查发现，**当前交付缺少关键的用户可见表现层实现**：
1. **表现层与用户提示缺失**：`DEVELOPMENT.md` §5.6/§5.7 明确要求“首局首坎温和站稳提示（首次遇到坎提示一次，之后不再提示）、站稳视觉/步态、自动轻跳/攀坡表现”。PR #14 的生产改动仅涉及 `app/.../domain/walk/` 下的 `TerrainMotor.kt` 与 `VirtualWalkController.kt`，在 UI 层（`SessionViewModel.kt`、`SessionScreen.kt`、`ForestShell.kt` 等）完全没有任何消费者来调用 `consumeStabilizeHint` 或消费 `gait` 步态。虽然作者自检报告中诚实列出“站稳提示的 UI 呈现待接”，但这是 SW-005 本身的验收门禁，不能推迟到处于 queued 的下游任务 `SW-007`。
2. **同局恢复生命周期语义不闭环**：若用户在同一会话（同 sessionId）中已在首坎触发并消费过站稳提示，后续若发生退入后台/暂停/进程重启并恢复快照，重建状态机时不应重置该标志导致同局内再次弹出“首坎提示”。
3. **死区边缘输入边界覆盖不足**：需补齐当输入位移极小（处于死区边缘 $d \in [0.01, 0.08]$）且接近坎时的自动化动作测试，验证不产生非预期位移刷新，严格遵循速度帽与松手即止规则。

因此，判定为 **`changes_requested`**，要求 ZCode 在本分支追加提交产出 R2，补齐表现层与回归证据后重新提验。

## 2. 缺陷清单 (Findings)

### P-01 (Severity: P1) - 缺少 UI 表现层与温和站稳提示接入
- **相关文件**：`app/src/main/java/com/sensewalk/app/ui/session/SessionViewModel.kt`, `SessionScreen.kt`, `ForestShell.kt`
- **问题描述**：`DEVELOPMENT.md` §5.6/5.7 规定：首次遇到坎时需向用户弹出温和站稳提示一次，并在越坎时展现步态/轻跳变化。当前 PR 仅暴露了 `consumeStabilizeHint()` 与 `TerrainMotor.Gait` 接口，UI 没有任何消费者。必须在 ViewModel/Screen 中消费提示并展示给用户，且支持 reduceMotion 设置；动画表现不驱动真实距离。

### P-02 (Severity: P2) - 快照恢复时同一 sessionId 提示二次弹出风险
- **相关文件**：`app/src/main/java/com/sensewalk/app/domain/walk/VirtualWalkController.kt`, `SessionStateMachine.kt`
- **问题描述**：若同一局在首坎已消费过提示，恢复时因重建控制器可能再次将 `hasShownStabilizeHint` 视为 false，导致同局重复播报。需确保同 sessionId 恢复时保持“同局仅提示一次”的产品承诺。

### P-03 (Severity: P2) - 摇杆死区边缘输入自动化动作与速度约束
- **相关文件**：`app/src/test/java/com/sensewalk/app/domain/walk/TerrainMotorTest.kt`
- **问题描述**：需要补齐当摇杆处于微输入（如死区边缘 $d \in [0.01, 0.08]$）时接近坎的单测，验证自动越坎动作在无有效推进输入时不会持续推进米数，确保速度帽与输入规则完全一致。
