## 2. 核心缺陷修复与验证结论

### 2.1 R3-01 生产入口测试标记隔离（修复原 R2-01）
- **修复实现**：生产默认入口严格检查并拒绝 `_fixture_mode` 及 `_expected_registry_status` 字段，试图在 manifest 中内嵌测试标记绕过生产门禁的行为会被直接阻断；测试 harness 必须显式通过 CLI `--fixture-mode` 旗标驱动。
- **实测结论**：默认入口对内嵌 `_fixture_mode` 的反例准确报错 `manifest_field__fixture_mode_forbidden`；CLI 模式下严格保持审批链校验。验证通过。

### 2.2 R3-02 真实半透明像素判定（修复原 R2-02）
- **修复实现**：`real_decode_image` 调整为统计 $\alpha < 127$ 的半透明像素比例；全不透明图（如背景填充、未抠图素材）其半透明像素比例为 0.00%，低于 0.1% 阈值，被准确拦截。
- **实测结论**：`negative_opaque_layer` 准确报错 `layer_mist_opaque_real: 半透明像素 0.00% < 0.1%`。验证通过。

### 2.3 R3-03 检查图 4 件套强制完整性（修复原 R2-03）
- **修复实现**：`check_required_checks` 强制校验 `alpha_mask`、`black`、`white`、`magenta` 4 种背景检查图；即便 manifest 的 `checks` 字段声明为空数组，预检脚本仍按图层与合同命名约定自动推导并检索物理文件是否存在。
- **实测结论**：`negative_missing_check` 准确捕获缺失项并报错 `layer_mist_check_required_path`。验证通过。

### 2.4 R3-04 API 账本非负整数与跨 revision 累计一致性（修复原 R2-04）
- **修复实现**：API 字段严格校验 `isinstance(v, int) and v >= 0`；读取 `state/minimax.json` 的历史账本基线（baseline=14），累计值小于历史或小于本轮声明均判定违规。
- **实测结论**：`negative_negative_api_cumulative` 准确阻断负数与倒退累计，报错 `api_field_api_attempts_total: 必须为非负整数, 实际 -1`。验证通过。

### 2.5 R3-05 严格双向批准链核验（修复原 R2-05）
- **修复实现**：`check_approval_chain` 全面核验 `registry.latest_handoff.head_commit == handoff.head_commit`、`registry.latest_review.reviewed_commit == handoff.head_commit` 以及 `verdict == approved`。
- **实测结论**：反例中任何 head commit 篡改、未批准声明或 SHA 不匹配均被严格拦截。验证通过。

### 2.6 R3-06 动态从 design-spec 读取图层（新增能力）
- **修复实现**：彻底移除了硬编码的雨林图层常量，改为从 `design_ref.spec_file` 动态解析 `layers` 列表。
- **实测结论**：图层数量不匹配或未知图层均被动态识别并拒绝。验证通过。

### 2.7 R3-07 真实超预算隔离反例（修复反例尺寸问题）
- **修复实现**：新建 `negative_real_oversize_layer`（单层 5.56 MB，远超 400KB 门禁）与 `negative_real_oversize_scene`（全景 27.44 MB，远超 2MB 门禁）。
- **实测结论**：两组反例真实触发 `layer_mist_budget_real` 与 `scene_budget_real` 门禁并被正确拒绝。验证通过。
