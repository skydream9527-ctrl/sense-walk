## 审核结论与核心核查

在 R1 退回（`changes_requested`，P-01/P-02/P-03）后，ZCode 提交了业务修订 `7b17424`，并于 `0765a82` 干净同步最新 main，解决 `state/zcode.json` 冲突（保留 SW-001 与 SW-010 双任务索引），且追加了 Markdown base SHA 笔误纠正文件。

Antigravity 通过独立测试套件 `tools/qa/test_pr1_r2_verification.py` 与云端 249 项全量单测日志（run 38554272476）对 Kotlin 源码和生命周期进行了完整复验：

### 1. P-01：detector 实际注册结果与脚步音回退验证（通过）
- **实现检查**：`StepSensorSource` 引入纯 Kotlin `SensorPort`，在 `start()` 中捕获 `port.registerDetector(onDetectorStep)` 实际返回值记录于 `detectorRegistered`；暴露 `cueAudioFromDistance = started && !detectorRegistered` 与 `detectorActive = started && detectorRegistered`。
- **服务接线**：`WalkForegroundService.setupSession` 明确赋值 `sensory.stepAudioFromDistance = sensorSource.cueAudioFromDistance`。
- **行为核验**：
  1. 当 detector 硬件存在但系统注册返回 `false` 时，`cueAudioFromDistance` 为 `true`，跨过 100m 步幅解锁门后由距离增量稳定触发脚步音（`playStep` 真实出声），不再发生实走静音；
  2. 当 detector 注册成功时，距离脚步音保持静默，脚步音仅来自 detector cue，不存在双倍出声；
  3. 当无 detector 硬件时，自然回退为距离驱动脚步音。

### 2. P-02：同刻合并与未封顶步数带回（通过）
- **实现检查**：`RealWalkEngine.kt` 在 `intervalMs <= 0L` 分支中直接返回 `StepDelta(0f, 0L)`，不再推进 `lastAcceptedCount` 与 `lastAcceptedMs`，步数完整保留在后续增量计算中。
- **反例复测**：
  - 审核反例 `(0,0) → (1,1000) → (2,1000) → (3,2000)` 依次产出 `0m, 0.7m, 0m, 1.4m`，3 步总计 2.1m，完美吻合 1.4m/s 硬顶速率且未吞噬第 2 步；
  - 低步数合并（t=0 时 2 步，t=2000ms 时 2 步）累计 1.4m（cap 为 2.8m，未被封顶掩盖），证明步数真实带回；
  - 暂停与重定基线：`pause()` 或 `restartBaseline()` Armed `rebasePending = true`，未计距的合并批在暂停期间被干净丢弃，恢复后首个事件仅建基线，不跨暂停期补算。
