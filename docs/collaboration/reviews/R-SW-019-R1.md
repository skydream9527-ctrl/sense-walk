## 1. 源码与架构变更独立审计

针对 `4f57659e00e0267be03a0a7b966cacba8387c5ee..a666b76793a77039df9e435d7877bb6fd55a4aec` 的 13 个变更文件进行逐文件审查：

1. **图层位图异步预热、解码与单飞缓存（`LayerImageCache.kt` / `ForestLayerImages.kt` / `ForestShell.kt`）**:
   - 移除原本在主线程 `remember(assetPath)` 内部同步执行的 `assets.open + BitmapFactory.decodeStream`。
   - 引入进程级 `LayerImageCache`（默认上限 `32 MiB`，按字节淘汰 LRU）与 `inFlight` 单飞去重。
   - **关键竞态修复核验（`a666b76`）**：在 `getOrLoad` 的 `finally` 块中清理 `inFlight` 时，后续等待协程若遇到被取消的 `Deferred`，会重新发起解码并在锁内通过 `if (load.isActive) inFlight[key] = load` 仅将仍活跃的任务写回 `inFlight`，彻底消除了取消瞬间 `finally` 先于写回执行导致的已取消 `Deferred` 残留竞态。
   - **未就绪回退契约**：`ForestShell` 在进入会话时通过 `LaunchedEffect(layers)` 在 `Dispatchers.IO` 并发预热全部图层；当某图层达到 `atMeters` 但位图尚未解码完成时，回退至已有的程序矢量绘制路径（`drawLayerFallback`），绝不渲染白块、破碎占位或闪烁。
2. **场景目录缓存（`SceneCatalogCache.kt` / `SceneCatalog.kt`）**:
   - 引入 `SceneCatalogCache` 缓存 `scenes/index.json` 与各场景配置，并向 `SenseWalkViewModel`、`SessionViewModel`、`WalkForegroundService` 提供只读透传视图，消除了进入会话、前后台切换与完成结算时的重复 JSON IO 解析。
3. **高频状态读取下沉（`SessionScreen.kt` / `RealWalkContent.kt` / `RealWalkSessionScreen.kt` / `ForestShell.kt`）**:
   - `ForestShell` 使用 `rememberUpdatedState` 持有高频 `progressMeters`、`stepFrequency`、`elapsedMs`，使 `Canvas` DrawScope 与动画循环仅在绘制阶段读取最新值，避免外层 `Box` 每帧重组。
   - 虚走与实走界面的脉冲圆与旅人徽章缩放下沉至 `Modifier.graphicsLayer { ... }` lambda 阶段；高频米数文本使用预格式化字符串并隔离在独立叶子组件中。
