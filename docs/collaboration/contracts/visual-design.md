# 图片设计规范与交付契约 v1

本规范约束 Trae Design 的图片设计与跨角色交付。产品规则以 DEVELOPMENT.md 为准，当前正式配置以已审核 SceneConfig 为准。设计意图与实际图片/Android验收是不同交付。

## 1. 美术语言与场景身份

采用安静的二维插画、干净剪影、低饱和色、柔和光线与适量留白，避免过密写实纹理、强烈闪光、恐怖元素或竞技HUD。旅人沿画面向右行走，使用侧视/轻微3/4侧视；不改成第一人称纵深道路。

| 场景 | 视觉身份 | 禁止混淆 |
| --- | --- | --- |
| 森林800m | 干叶、通透树荫、少量暖褐与林光 | 不画成湿雾浓密雨林 |
| 雨林900m | 湿绿、雾气、阔叶、藤蔓、水气 | 不复制森林换标题或色相 |
| 城市1000m | 克制街灯/建筑剪影、冷灰蓝、安静街角 | 不用霓虹/车流制造刺激 |
| 沙漠1200m | 沙丘、低饱和暖沙、广阔留白 | 不用刺眼日光和炫目颗粒 |
| 夜径700m（可选） | 冷暗路径与少量暖点 | 不作为本轮新增主场景 |

森林基准色板：void #060806、轮廓 #1A2820、树干 #2D4A3E、林光 #8FA87A、落叶 #6B8F71、暖褐 #A89060。其他场景使用对应design单页；变化提案必须指出影响，不暗改现有已采用规则。

## 2. 构图与坐标

- 设计基准1080×1920，补1080×2400长屏及390×844小屏裁切参考；图片画布与真实app内容区的安全区关系注明。
- 坐标统一归一化0–1，所有分层使用同一画布、光源、地平线和脚底基线。森林当前程序旅人锚点x=.34、脚底y=.865，先保持；调整列为单独提案，不直接修改生产代码。
- 下方45%为摇杆触摸区，上方有米数/暂停/放弃操作：图片不烘焙按钮、文字或摇杆；操作区避免高对比杂乱纹理。设计标注可显示参考框，最终素材导出必须去掉。
- 只展示美术效果不等于触摸/无障碍已验收。实走无摇杆，同一景色需能用于虚走与实走。
- 首页只给克制色壳/小范围提示，不预览完整终景。初始黑幕仍可有独立操作说明与很弱的程序旅人轮廓，不能提前揭示风景。

## 3. 分层与距离阶段

每景最多五个外部视觉层，void与旅人程序绘制。parallax和overlay分开设计，不把整张完整风景切成五张重复底图。

| 森林layer | 解锁m | 目标opacity | fadeMeters | 设计内容 |
| --- | --- | --- | --- | --- |
| tree_outline | 80 | .60 | 20 | 远处树林轮廓，树间真透明 |
| tree_trunks | 240 | .70 | 25 | 中景树干和少量林间光，不另画地面 |
| leaf_path | 400 | .80 | 25 | 下部干叶/土路，上部透明 |
| light_shows | 600 | .65 | 30 | 少量斜光/远鸟，不附带第二套背景 |
| clearing | 760 | .90 | 25 | 安静空地微光，无重复树林/棋盘 |

此表为当前配置的设计参考，runtime字段由SceneConfig/DEVELOPMENT拥有。SW-011不改变数字；未来配置变化需契约revision与双方确认。展示0/100/265/425/630/785m六阶段；opacity按既有smoothstep与fadeMeters合成。不要把预览用的层透明度烘焙到最终RGB/alpha，以免应用二次衰减。停走冻结揭示程度。

## 4. 设计检查与导出

- 可编辑源优先采用工具真实原生文件或SVG/HTML/CSS等可编辑格式；同时导出PNG预览。只有截图必须标明，不伪造图层/矢量/PSD文件。
- 参考图与正式可用素材标识分开：design_reference / layer_export_reference。PNG真实RGBA，不把棋盘画进背景；简单柔光优先渐变。
- 若提供分层导出，每层至少黑/白/洋红底检查，中央和边缘放大看图，不能只用alpha覆盖率判合格。深色主体不能被抠图误删。
- 需持续横移的层注明tileable=true/false；true时给三次拼接与多个偏移预览。有限滑动与循环平铺不同，设计不能假设当前渲染已经支持平铺。
- 最终素材规范仍由visual-assets契约执行：每层≤400KB、每景≤2MB。设计原稿/参考可更大，但不放app/assets；放大旧768×1376需注明，不称原生1080。

## 5. 文件包与机器可读清单

```text
design/05-visual-design/SW-xxx/r1/
  README.md                  # 意图、差异、待实现/待验证
  design-spec.json           # 画布/色板/锚点/图层/阶段/限制
  design-manifest.json       # 本轮每个实际文件及SHA256
  prompts.md                 # MiniMax逐层执行提示词和负提示
  source/                    # 实际可编辑源
  references/                # 风格参考，注明来源/用途
  previews/                  # 分层标注、阶段/比例裁切预览
  exports/                   # 可选分层导出参考，不自动成为入包素材
```

清单结构见 [design-manifest示例](../templates/design-manifest.json.example)，规格字段见 [design-spec示例](../templates/design-spec.json.example)。包含schema_version/task_id/revision/producer、spec_file、files（path/sha256/bytes/role）和limitations；path相对repo根。所有说明/source/reference/prompt/preview实际文件均列清单，不引用缺失文件；清单本身不列自身哈希，避免递归。spec记录实际scene_id、基准尺寸、坐标、palette、layers、预览进度、源码/配置依据与未实现限制。选择颜色与构图的理由写清楚，不只给最终图。

给MiniMax的每层提示词至少有：layer ID、实际参考文件、主体、禁止同层外内容、画布/透明、光源/色板、裁切/基线、拼接、禁止文字/UI/棋盘的负提示。提示词是可追溯生产输入，不代替真实素材。

## 6. 审核与消费

Trae只声明design_candidate。Antigravity独立审核设计head与manifest全部文件哈希；批准后才称approved_design。MiniMax新场景素材manifest需 `design_ref`（设计任务/已批准handoff/spec路径/spec_sha256），旧设计变化则失去原来引用的批准，必须重审。ZCode入包仍做实际Android验证。

设计新revision获批时，协调者将受影响的当前素材任务登记rework，并重新安排接入依赖；不能继续声称旧素材匹配新设计。历史设计/素材文件及批准记录保留，校验它们在当时引用的确切设计head/哈希与独立批准；历史可查看不代表当前可入包。新交付或仍登记accepted的交付必须引用当前批准设计，不能用归档记录跳过新审稿。

当前SW-002为现有森林透明/光效修复，可沿已有设计继续，不因新增角色被重置。SW-006雨林制作必须等待SW-012已批准设计；本轮设计不是授权改标准距离、地图规则、已有角色动画或整个UI布局。
