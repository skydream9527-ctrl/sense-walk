# SenseWalk · ZCode 开发计划与提示词

交接日期：2026-10-12。交付方式：**功能开发 + GitHub Actions 云端检查/打包 + GitHub 下载交付**，无需完善本地 Android 环境。依据 [DEVELOPMENT.md v0.8](../DEVELOPMENT.md)。本文将 M0–M3 拆成 9 个可单独交付的任务，不新增产品规则。开发前以 ZCode 实际拿到的源码为准，重新核查进度。

## 使用方法

1. 让 ZCode 获取 [GitHub 仓库](https://github.com/skydream9527-ctrl/sense-walk) 当前 main；或下载 Actions / Releases 中的源码交接包，包内包含计划、提示词、设计和代码。
2. 在项目根目录开始，先发送「总提示词」，再发送 T01 的阶段提示词。
3. 每个阶段完成后，检查实际变更、测试结果和演示；发送下一阶段编号。新会话需同时补总提示词和本阶段提示词。
4. T01–T08 是可由开发工具执行的工作；T09 还包含真人内测和实体手机验证。无法实际执行的部分必须标记「待验证」，不能据此宣称最终 MVP 已验收。
5. 本地只需能编辑源码和提交代码；JDK、SDK、Gradle、测试和 APK 打包由 GitHub Actions 执行。本地缺 SDK/模拟器不阻塞开发；云端失败按日志修复。日历工期等 T04 跑通闭环后再估算。

```text
请接手当前仓库的慢行 SenseWalk Android 应用开发。你需要实际修改源码、构建、验证并交付本阶段结果，而不只是输出方案。

先读取仓库的 AGENTS.md（如存在）、README.md、DEVELOPMENT.md、docs/zcode-handoff.md，并按 design/README.md 的顺序了解设计包。检查 git status 和现有代码，保留所有已有未提交修改，不能 reset/覆盖用户工作。以 DEVELOPMENT.md v0.8 为规则与进度依据；若原型、旧示例与正文冲突，采用最新明确规则，记录差异，不把 HTML demo 当 Android 实现。

这是 Kotlin + Jetpack Compose 项目，minSdk 26，compileSdk/targetSdk 35，包名 com.sensewalk.app。现有代码仍是静默计时骨架。先确认实际源码状态，再按本次指定的 T01–T09 阶段开发；完成当前阶段后汇报，不自动扩大到后续阶段。合理实现细节可以自行决定；涉及标准距离、交互主规则或产品范围的改变，先列出具体选项再等待决定。

必须保持：
1. 进度来自有效距离；未满 requiredDistanceMeters 结束只能是放弃，满距只通关一次。UI 动画、计时、插值不能生成距离。
2. 舒适摇杆用 comfort_v1：中段更快、拉满更慢，峰值 1.18 m/s，硬顶 1.4 m/s；按文档平滑与惯性，不添加倍速/冲刺/自动托管。
3. 会话从黑幕与静音起；音/振/视按 atMeters 解锁。视觉用 fadeMeters；脚步与振动跟步伐，停走不再揭示；环境音淡入时停走冻结增益。
4. 主动放弃结束本局；被动中断才可在 30 分钟内选择恢复。虚走后台暂停、回前台不自动前进；实走锁屏由前台服务继续。终态清资源、清恢复快照并吸收迟到事件。
5. 计步实走与虚走共用门禁，不共用路径方向检测：counter 首次只设基线；处理批量/重复/乱序/重启；只有 counter 没有 detector 也可走，不密集补播步声。不承诺识别原地踏步或倒走。
6. 森林 800 m、雨林 900 m、城市 1000 m、沙漠 1200 m；夜径 700 m 可选。GPS 辅助放 P2，不强制定位，不新增账号、网络遥测、排行或跳过机制。
7. 地形以减压为目标，先缓坡再自动越坎，不做扣命/QTE；无障碍模式不放宽门禁。

优先复用当前结构，领域规则保持纯 Kotlin、可单测，UI 只输入和渲染。会话由 ViewModel/会话控制器持有，实走服务使用同一个状态来源，避免 UI 和 Service 双重计距。仅按必要性添加依赖；不做与阶段无关的重写或批量升级。

每阶段：简述源码差距与实现顺序，随后实现功能。无需安装或完善本地 JDK/SDK/Android Studio/模拟器；把必要测试与校验接到 GitHub Actions，提交当前阶段代码后查看云端 test/lint/build 日志，修复失败并再次验证。已有 Actions 工作流优先复用。云端等待期间可以继续不依赖结果的开发，但未通过的检查不能标为通过。测试应覆盖行为边界，不用空测试凑数；不伪造真机或真人结果。
```

### T03 · 纯 Kotlin 领域规则


### T06 · 实走与前台服务

```text
请执行 T06，计步、权限和前台服务作为一套实现，不把服务延期。

实现 TYPE_STEP_COUNTER 为唯一计距源：首次事件只设基线，之后 Δsteps×strideMeters，增量不超过 1.4×事件间隔；步长默认 0.70 m，范围 0.45–0.95。时间使用同一单调时间基准，处理重复、乱序、批量、读数下降与重启。TYPE_STEP_DETECTOR 仅触发已解锁脚步/振动，不重复计距；只有 counter 无 detector 时仍可实走，不密集补播批量步数。

检测传感器、按需请求 ACTIVITY_RECOGNITION/通知权限。无 counter 或拒绝计步授权可退回虚走，不骗进度；传感器暂时无事件给可理解状态，不靠超时制造步数。

从可见 Activity 在权限满足后启动 WalkForegroundService。依据实际功能核查官方 Android 服务规则并声明 health/mediaPlayback 所需类型和权限，兼容 minSdk 26 到 targetSdk 35。UI 与 Service 使用同一个会话状态来源；重建 Activity 不重新启动第二份计距引擎。通知提供返回与停止，停止按放弃处理。完成/放弃后注销传感器、停止音振和服务。

本阶段不申请定位、不做 GPS/车载判定，也不承诺判断倒走或原地踏步。亮屏渲染已走出的视觉状态，锁屏不渲染。

完成 S5/S8 的事件注入测试，构建/lint，并在可用真机验证锁屏 15 分钟、权限拒绝、有 counter 无 detector、通知停止、UI 重建。真机缺失时交付源码和模拟验证，但不得宣称锁屏实测通过。
```
